## 테스트 요청

1. 새 서버의 실제 도구와 context를 확인하고, Azrael 클라이언트에 연결된 이 세션에서 정상 사용되는지 확인해주세요. 처음에는 관찰·선택 창 조회 등 영향이 작은 작업부터 진행하세요.
2. 새 임시 앱/테스트 문서만 사용해 승인 요청과 허용 후 입력을 확인하세요. 실제 권한 UI의 승인은 사용자가 직접 해야 합니다. 모델이 승인창을 클릭하거나 CDP·설정 파일 수정으로 승인/전체 허용을 만들지 마세요. 승인 대기라면 사용자가 해야 할 동작을 설명하고 기다리세요.
3. 입력은 관찰한 실제 대상에만 수행하고 UIA 입력/버튼 동작의 결과를 다시 읽어 확인하세요. 좌표 입력을 시험한다면 먼저 사용자에게 잠시 입력 중지를 요청하고, 간섭·오래된 참조·결과 불확실 오류를 자동 재실행하지 마세요. 원시 입력 전달만으로 성공을 단정하지 마세요.
4. 새 MCP의 자체 설정/승인 창 관찰·제어가 거부되는지 확인하세요. 설정·승인 UI를 제어하는 우회 방법을 시도하지 마세요. 보호 앱/사용자 중지/거절을 존중하세요.
5. 반복 가능한 단위 확인이 필요하면 기존 `npm test`를 사용할 수 있습니다. `scripts/verify-windows.cjs`의 기존 CDP 승인 자동화는 이전 통합 검증용이므로, 이번 독립 클라이언트 실사용 승인을 대체하는 방법으로 사용하지 마세요.
6. 실제 성공/실패/사용자 승인 대기/미검증을 구분하여 한국어로 보고하세요. 호출한 서버 이름과 실제 결과, 필요한 수정 제안을 포함해주세요.
