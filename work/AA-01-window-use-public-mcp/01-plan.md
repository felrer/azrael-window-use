상태: 구현·로컬 배포 패키지의 실제 9개 항목 검증 완료. 사용자가 명시적으로 승인한 임시 자료 보관 예외와 함께 작업 완료.

# Window Use 독립 배포

## 목표와 권한

- 바탕화면 `azrael-window-use-mcp`를 별도 Git 프로젝트로 만든다. 원본 Azrael의 사용자·동시 작업 변경은 수정하거나 커밋하지 않는다.
- Windows x64의 로컬 대화형 데스크톱만 지원한다. Azrael·VS Code·별도 Node 설치 없이 실행 가능한 배포물을 만든다.
- 현재 소스의 Window Use 기능과 정책을 재사용한다. 연결은 표준 MCP stdio이며 Codex 전용 메타데이터를 신뢰하지 않는다.
- 기존 UI에서 필요한 설정 행·테마·승인 요소를 가져와 작은 프레임리스 창과 트레이를 제공한다. 도구에 권한이 필요하면 승인 UI를 띄운다.
- 설정·승인 UI는 기존 보호 앱 블랙리스트로 관찰·제어 차단하고 데스크톱 캡처에서 마스킹한다. 모델에 권한 변경 도구를 제공하지 않는다.
- 기본 앱별 승인, 관찰 전용 및 전체 허용 모드를 설정할 수 있다. 전체 허용에서도 보호 앱과 사용자 중지가 우선한다.
- 앱별 일시 권한은 연결에 묶고 데스크톱 권한은 영속화하지 않는다. 거절·시간 초과·철회·연결 종료는 실행을 허용하지 않는다.
- 공개 저장소 업로드·원격 push·배포 사이트 게시·인증서 구매는 현재 실행 범위에 포함하지 않는다.

## 구조와 순서

1. 기존 정책·네이티브 엔진·UI와 라이선스 출처를 고정된 프로젝트 소스로 가져온다.
2. 독립 권한/연결 서비스와 네이티브 어댑터를 연결한다. UI는 제한된 preload IPC만 사용한다.
3. UI·네이티브 빌드·프로토콜 준비를 독립 진행하고 최종 통합 시 고정 입력을 사용한다.
4. 정책 거부·승인·중지·변경·오래된 참조·자체 UI 보호를 테스트한다.
5. 실제 Electron stdio 실행과 실제 Windows 창 캡처·조회·조작, 라이트/다크 UI를 검증한다.
6. 설치/휴대 배포물의 동일성·Azrael 비의존 실행을 검증하고 필요한 문서와 관련 소스만 커밋한다.

## 검증·정리

- 보존 대상: 선택 창 UIA·전체 화면 입력·마스킹·점유·매크로·즉시 중지·변경된 창 검증. 실제 지원 여부는 개별 검증 결과로 기록한다.
- 승인 화면은 실제 사용자가 클릭하거나 허용된 테스트 경로로 검증하며 공개 실행 경로에 자동 승인 우회 기능을 넣지 않는다.
- 개발/테스트 데이터·로그는 artifacts 아래 작업 소유로 기록하고 불필요해지면 일반 삭제로 제거한다. 최종 패키지와 최소 검증 기록은 납품물이다.
- 원본 라이선스와 의존성 고지 유지. 공개 배포 패키지 서명·클라이언트별 실사용 확인의 실제 범위를 보고한다.

## 진행과 결과

- 사용자 재개 승인 후 동일 배포 파일의 실제 입력 검증을 실행한다. 새 출력은 artifacts/acceptance 아래 독립 실행 그룹으로 관리하며 기존 중복 등록된 검증 경로를 재사용하지 않는다.

- 원본 작업 트리에 기존 변경 1,137개가 있어 원본은 읽기만 한다.
- 독립 프로젝트·소형 프레임리스 UI·연결별 권한 서비스·현재 사용자 named pipe/콘솔 실행기를 구현했다.
- 표준 SDK stdio 연결, 실제 WinForms 창의 승인 거절/승인 후 UIA 수정·버튼 실행, 라이트/다크 렌더링, 전체 허용에서도 자체 UI 조회·제어 차단과 네이티브 마스킹을 실제 확인했다.
- 네이티브 35개 테스트 통과/4개 live fixture 제외, 권한/런타임 7개 테스트 통과. 원본 코드의 부분 필드 조회와 desktop_target hex 형식 문제는 복사본에서 수정하고 PATCHES.md에 기록했다.
- 앞선 실제 좌표 입력은 입력 간섭 보호로 거부되었다. 사용자가 재개한 입력 없는 구간에서는 전달이 진행되었으나 버튼 postcondition이 실패했다. 테스트 앱을 네이티브 broker와 같은 per-monitor-v2 DPI 인식으로 바꾼 뒤 물리 좌표가 일치하여 실제 버튼 클릭을 확인했다. 배포 프로그램이나 보호 규칙은 바꾸지 않았다.
- 네이티브 빌드 임시 캐시·로그 269,241,664 bytes를 관리 도구로 삭제했고 최소 검증 기록을 native-verification.json에 보존했다.
- 실패한 패키징 3회는 각각 author 메타데이터, ASAR 검증 경로 구분자, ZIP 엔트리 구분자 문제로 exit1이었다. 수정 후 새 고정 입력의 패키징은 exit0(54.10초)이며 실패 상태를 성공으로 바꾸지 않았다. 실패한 복사본은 진단을 마쳐 정리한다.
- 최종 패키지: artifacts/releases/0.1.0-20261106T050046680-0236951431-f711e6. ZIP 162,317,288 bytes, SHA256 d1a5b2ca5c330ee4801e7334fe235016c6c54eafc2ff3091f153967c97410da4. 멤버 해시, native manifest, asar 동일성, 호스트 RunAsNode 비활성화를 검증했다.
- 이 패키지의 실제 공개 실행기로 9개 항목(표준 stdio/24개 도구, 자동 승인창·거절, 승인된 실제 UIA 입력, 라이트/다크 UI, 자체 UI 보호, 데스크톱 마스킹, 물리 좌표 입력, Stop/재개, EOF 종료)을 모두 통과했다(exit0). 좌표 입력 1회, 외부 마우스 이벤트 0개, 실제 버튼 카운터 1→2를 확인했다. package-verification.json에 독립 postcondition과 정확한 배포 해시를 보존했다.
- 서명·클린 머신·실제 MCP 클라이언트별 설치는 미검증이며 원격 공개 업로드하지 않았다. 일반 네이티브 테스트에서 제외한 live overlay/notification 4개 fixture의 검증까지 확대하지 않는다.
- 실패한 패키징 3개 그룹의 9개 항목을 관리 도구로 삭제했고 모두 remaining=false를 확인했다. 추가 임시 자료 127,317,506 bytes는 검증 상위 경로와 새 하위 경로의 중복 등록 때문에 whole-group 검토가 차단한다. 사용자가 해당 정확한 자료를 충돌 해소 전까지 보관하도록 승인했다. 강제 삭제·등록 파일 직접 수정 없이 보존하며 cleanup-pending.json에 정확한 경로와 해소 조건을 남겼다.
- 마지막 실제 입력 검증을 마쳐 고정 패키지 소스/로그 묶음과 새 테스트 프로필의 실행 참조는 종료되었다. accepted-package-staging 및 quiet-input-acceptance 그룹의 합계 88,387,339 bytes를 관리 도구로 삭제했고 3개 항목 모두 remaining=false를 확인했다. 최소 검증 기록은 work에 보존했다. 최종 배포 ZIP·풀린 실행 파일·개발용 native runtime은 납품물이다.
- 중복 등록 충돌 자료 127,317,506 bytes에 대해 사용자가 “충돌 해소 전까지 보관 허용”으로 명시적으로 승인했다. 예외는 cleanup-pending.json의 정확한 경로/두 그룹에 한정되며, 지원되는 소유자 절차로 중복 등록이 해소되고 새 whole-group 검토가 통과하면 정리를 재개한다. 보관 승인은 삭제 보호 우회를 허용하지 않는다. 원본 Azrael 정리 엔진을 수정하거나 registry JSON을 직접 편집하지 않았다.
- 기존 실제 Windows 수용 검증을 보존하는 이유는 향후 실행기/패키징/권한 callback 변경에서 stdio 경계·보호 앱 전달·DPI 좌표 처리 누락을 반복할 수 있기 때문이다. 별도 테스트 파일이나 새 모의 구현을 추가하지 않고 기존 검증과 fixture를 수정했다.
